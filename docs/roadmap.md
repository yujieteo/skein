## Direction after phase 6

The language comes first. After the current work, `physics` becomes a core
part of the language. A person writes arbitrary code with the `physics`
keyword, and Skein builds a custom solver from it that is highly optimized.
Reason: the captain stated this as the aim of the project.

Option A comes first. The `physics` block is generic: a person keys in any
equation, and the compiler makes the solver. The generic path never calls a
built-in family. The built-in families (heat, elastic, flow, edge, shells and
the others) stay, and they form the standard library in their own package.
Each built-in also gets a standard-library `physics` block as a port. The port
matches the built-in within 1e-10. The built-in is not deleted. The stage
after A is user-written solver algorithms (phase 11).

Rule for the generated solver in A: it does only the work that the
equations need, on the CPU and on the GPU. It has no repeated assembly, no
needless copy, no allocation in a loop and no extra pass over the data. The
generated code stays simple. A does no tuning. Reason: the captain wants a
non-pessimizing solver that is simple to generate. Speed work comes later
(phase 10).

Femahoy cases keep using the built-ins, as they do today. They test the
built-ins now. Later, the same cases also test the generic `physics` block.

Static analysis and lint: Skein's own Goose code gets `/guardrails` level
linting, and the tests run under ASan and UBSan builds. Both are done and
run in `./build.sh test`. Goose is experimental, so the lint rules grow
with the language.

Phases 7 and later mature the physics language and its standard library.

### Design task: language gaps

Four gaps in the Skein language, in this order:

1. Expected answers. A first-class `expect` or reference construct has a
   value, a tolerance and a source. Reference values that are now in
   comments become checked results. Examples: u_y = 10.5953 mm at corner A,
   S11 = 0, and the Rayleigh value 1892 0.5829156886.
2. Hidden defaults. The method of each block is visible in the program, or
   `skein check` prints it. Examples: quadratic tetrahedra, the start value
   of Newton.
3. Conventions and roles. Sign and phase conventions, for example
   exp(im*omega*t), and the roles of regions are declarations. The compiler
   checks them.
4. Names and sources. A model or a value has a `doc` or `source` field, for
   example Table 1 of a paper.

Gate: each gap has a design note and a spec section. Each `.skn` example
that has a reference value in a comment has it as a checked `expect` with a
source, and `skein run` passes it. `skein check` prints the method of each
block that has no `method` line. A test shows that a wrong convention or a
wrong region role is an error of `skein check`.

Reason: the examples in `examples/` keep reference values, conventions and sources
in comments, where no run checks them.

## The end-to-end slice

One thin slice of phase 2 lands before phase 1 is complete. Reason: a Skein
model must give a measured result early. The slice is the package `runtime`
in `src/runtime/`. It has a box mesher with 27-node hexahedra (Q2), CG with
a Jacobi preconditioner, reactions and VTU output. The package `codegen` in
`src/codegen/` gives `skein run` for one linear static box: it generates a
Goose program that calls `runtime`. Phase 2 widens the slice to the
full runtime of [spec §18.4](skein_spec.md#184-the-runtime).

## Phase 1 in detail

Phase 1 adds no solver, except the end-to-end slice. Reason: the language is the product, and the
[LLM test](llm_test.md) can show a bad syntax before the solver costs time.

Phase 1 delivers:

1. the lexer and the parser of spec §2 and §3, with error recovery;
2. name resolution, types, dimensions and units (spec §4 to §7);
3. the geometry types and the region rules that need no mesh (spec §8);
4. the rules for fields, materials, physics, assumptions, conditions,
   methods and steps (spec §10 to §15), except the ones that need a mesh;
5. `skein fmt` and `skein check`, with TOON and JSON output;
6. a test for each error id.
